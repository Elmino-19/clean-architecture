# چارچوب گردش کار — کامندها و ایجنت‌ها

> مرجع کامل محتویات `.opencode/`. نسخه‌ی انگلیسی: [README.md](README.md).
>
> اگر فقط یک چیز بخوانی: **شروع سریع** و **گرامر**.

---

## ۰. شروع سریع

```text
/go scan --modules key,example                    ← یافتن ایرادها، فقط خواندنی
/explore --modules knowledge                      ← توضیح معماری و جریان
/plan  --modules user -n 2 -- هدف آزاد             ← تسک‌لیست مرتب، بدون کدنویسی
/craft --modules example -- ماژول نمونه را کامل کن    ← پلن ← کدنویس×۳ ← بازبین
/mend  --modules key -- اصل commit در یوزکیس‌ها      ← اسکن ← پلنر ← ویرایشگر×N ← بازبین
/review --modules key                             ← فقط راستی‌آزمایی، هرگز اصلاح
/design -- محصول جدید                             ← فقط docs/sdd.md
```

---

## ۱. شکل کلی

```text
کاربر ──▶ /go | /scan | /plan | /craft | /mend | /review | /design
            │  (۸ فایل نازک، بدون هیچ منطقی)
            ▼
        orchestrator  (منشی)
        پارس · اعمال پیش‌فرض‌ها · یک‌بار کدگراف · dispatch · گزارش
            │  task(subtask)
            ├── analyzer   (فقط‌خواندنی)            ── بررسی
            ├── planner    (می‌نویسد: .me/runs)    ── پلن
            ├── coder      (می‌نویسد: app/, test/)   ── کد جدید
            ├── editor     (می‌نویسد: app/, test/)   ── اصلاح
            ├── reviewer   (make test/lint)         ── بازبینی
            └── sdd-writer (می‌نویسد: docs/)        ── طراحی (شاخه‌ی جدا)
```

منشی **هیچ دسترسی**‌ای برای خواندن کد، نوشتن کد یا بارگذاری اسکیل ندارد. او فقط
**کاتالوگ** را می‌شناسد (نام اسکیل‌ها و کاربرد یک‌خطی‌شان، نام ایجنت‌ها و حوزه‌شان)
و نه بیشتر. همین باعث می‌شود توکن و رفتار او ثابت بماند.

## ۲. گرامر

```text
<verbs> [--app be|both] [--scope all|module|layer|file] [--modules a,b]
        [--layers domain,application,infrastructure,presentation] [--files path,…]
        [--kind word,…] [-n N] [-- متن آزادِ هدف]
```

| توکن | مقدارها | معنی |
|---|---|---|
| `verbs` | `explore`, `scan`, `plan`, `craft`, `mend`, `review`, `design` | مرحله‌ها، به همان ترتیب |
| `--app` | `be` \| `both` | کدام سمت پروژه (این ریپو فقط بک‌اند دارد) |
| `--scope` | `all` \| `module` \| `layer` \| `file` | واحد کار |
| `--modules` | فهرست با کاما | نام ماژول‌های زیر `app/modules/` |
| `--layers` | فهرست با کاما | چهار لایه‌ی DDD |
| `--files` | فهرست با کاما | مسیرهای صریح |
| `--kind` | فهرست با کاما | محدودکردن اسکن به دسته‌های خاص از قوانین |
| `-n` | عدد | تعداد کارگر (پارتیشن‌های موازی) |
| `-- …` | متن آزاد | هدف؛ هرگز پارس نمی‌شود |

هرچیزی بعد از `--` هدف است و **هرگز** به‌عنوان flag تفسیر نمی‌شود. verb یا flag
ناشناخته **حدس زده نمی‌شود**: منشی متوقف می‌شود و می‌پرسد.

---

## ۳. پیش‌فرض‌ها (جدول حالت‌های استثنا)

آرگومان‌های نامشخص بی‌صدا حل می‌شوند و **هرگز** نیت کار را گسترده نمی‌کنند.

| نامشخص | پیش‌فرض |
|---|---|
| verb | `question` (کدام کار؟) |
| `--app` | `both` → کل ریپو |
| `--scope` | `all` → همه‌ی ماژول‌های زیر `app/modules/` |
| `--modules` | همه‌ی ماژول‌ها |
| `--layers` | هر چهار لایه |
| `--kind` | همه‌ی kindها |
| `-n` | **۳** |
| هدف برای `scan` / `explore` / `review` | از روی scope مشتق می‌شود؛ چیزی پرسیده نمی‌شود |
| هدف برای `craft` / `mend` / `plan` | **یک** `question` با پیش‌نویس مشتق‌شده از scope |
| `-n` > تعداد کارها | کلمپ می‌شود و در گزارش اعلام می‌شود |
| نبود `.codegraph/` | یک خط گزارش، سپس توقف |
| کارگر به سقف استپ خورد | گزارش وضعیت نیمه‌کاره، سپس «ادامه؟» |

مرحله‌هایی که خودکار اضافه می‌شوند، در گزارش اعلام می‌شوند و پنهان نمی‌مانند:

- `craft` / `mend` بدون `plan` → اول `plan` اجرا می‌شود.
- `craft` / `mend` بدون `review` → آخر `review` اجرا می‌شود.
- `mend` بدون `scan` → اول `scan` اجرا می‌شود (نمی‌شود یافته‌ی بی‌نام را اصلاح کرد).

## ۴. خط لوله و تسک‌لیست

```text
بررسی (explore|scan) → پلن → پیاده‌سازی (craft|mend) → راستی‌آزمایی (review) → گزارش
```

پلنر زیر مسیر `.me/runs/<timestamp>-<slug>/` می‌نویسد:

| فایل | نویسنده | کاربرد |
|---|---|---|
| `plan.md` | planner | هدف، وضعیت فعلی، مراحل مرتب، مرزهای ثابت، پارتیشن کارگرها، وارسی، ریسک‌ها |
| `tasks-1.md … tasks-N.md` | planner | **یک فایل برای هر کارگر**؛ مالکیت یکتا، پس تیک‌های موازی تداخل نمی‌کنند |
| `scan.md` / `map.md` | analyzer | یافته‌ها یا نقشه‌ی معماری |
| `review.md` | reviewer | انجام‌شده/نیمه/انجام‌نشده + خروجی واقعی `make test` و `make lint` |

قالب هر آیتم:

```markdown
- [ ] #3 · app/modules/key/application/use_cases.py
      operation: add GetKeyUseCase with an is_active filter
      rules: flush only, no commit; error shape from references/cross-cutting.md
      accepts: `make test` green; use case covered by a fake-repository unit test
```

**قواعد پارتیشن‌بندی برای `-n > 1`**

- هر کار دقیقاً متعلق به **یک** کارگر است. مجموعه‌فایل‌های یک ماژول هرگز بین دو کارگر
  تقسیم نمی‌شود.
- نقاط ثبت مشترک (`migrations/env.py`، `app/app.py`، `migrations/versions/**`) به یک
  کارگر داده می‌شود و در تسک‌فایلش علامت می‌خورد.
- کارگرانِ یک مرحله موازی‌اند؛ مرحله‌ها پشت‌سرهم.

## ۵. نقش‌ها، با جداسازی سخت

| ایجنت | اسکیل | `steps` | مجاز به نوشتن | تست | ممنوع |
|---|---|---|---|---|---|
| `orchestrator` | ندارد (فقط کاتالوگ) | ۲۵ | `.me/**` | خیر | خواندن کد، نوشتن کد، بارگذاری اسکیل |
| `analyzer` | `backend-development` | ۲۰ | `.me/**` | خیر | هرگونه اصلاح، dispatch کردن |
| `planner` | `backend-development` | ۱۵ | `.me/**` | خیر | نوشتن کد |
| `coder` | `backend-development` | ۴۰ | `app/**`, `test/**`, `migrations/versions/**`, `.me/**` | خیر | هر چیز بیرون از تسک‌فایلش |
| `editor` | `backend-development` | ۳۰ | مثل coder | خیر | گسترش دامنه، اصلاح موارد فهرست‌نشده |
| `reviewer` | `backend-development` | ۲۰ | `.me/**` | **بله، یک‌بار** | هرگونه اصلاح |
| `sdd-writer` | `software-design-document` | ۲۵ | `docs/**` | خیر | کد تولیدی |

قرارداد بین نقش‌ها:

- آنالیزور و پلنر **تسک‌لیست را می‌نویسند**.
- کدنویس و ویرایشگر **فقط** از آن پیروی می‌کنند، آیتم‌به‌آیتم، و در پایان `- [x]`
  می‌زنند.
- بازبین **فقط بررسی می‌کند** که آیتم‌های تیک‌خورده واقعاً انجام شده‌اند؛ هرگز اصلاح
  نمی‌کند و موارد باز را برای یک اجرای `mend` برمی‌گرداند.
- `make test` و `make lint` **یک‌بار در هر اجرا**، توسط بازبین، اجرا می‌شوند.

## ۶. پروتکل dispatch

هر فراخوانی `task` خودبسنده است — کارگر هیچ کانتکست مشترکی ندارد:

```text
subagent_type: coder
description:   craft — modules key, example
prompt:        ROLE: coder
               RUN: .me/runs/20260101-1200-key-crud/
               TASK FILE: .me/runs/20260101-1200-key-crud/tasks-2.md
               SCOPE: modules=[key] layers=[domain,application] files=[] kind=[]
               OBJECTIVE: add CRUD with cache tombstones
               OWNERSHIP: you own exactly these paths: app/modules/key/**
               FORBIDDEN: no other file; no test runs; report ≤10 lines
```

هر کارگر حداکثر **۱۰ خط** برمی‌گرداند: آیتم‌های انجام‌شده، آیتم‌های باز، فایل‌های
لمس‌شده، وضعیت تست. منشی هرگز فایل‌های آن‌ها را باز نمی‌کند.

---

## ۷. گزارش

بعد از هر مرحله:

```text
stage 2/4 · plan — planner · 11 items · tasks-1..3.md
```

و در پایان:

```text
| Stage | Agent | Scope | Result | Verification |
|---|---|---|---|---|
| analyze | analyzer | modules key, example | 14 findings (2 blocker) | — |
| plan | planner | same | 11 items / 3 task files | — |
| implement | coder ×3 | same | 9/11 done | — |
| verify | reviewer | diff + task list | 2 items open | make test ✓ · make lint ✓ |

Open items: <فهرست>   ·   Next step: <قدم بعدی>
```

هیچ مرحله‌ای بدون نقل قول واقعی کارگر یا خروجی واقعی دستور، «انجام‌شده» گزارش نمی‌شود.

---

## ۸. قانون کدگراف

همه‌ی نقش‌ها از قانون مخزن پیروی می‌کنند: **اولین** فراخوانی ابزار باید
`codegraph_explore` باشد (یا در شل `codegraph explore "<سؤال>"`). `grep`/`rg` در همه‌ی
ایجنت‌ها ممنوع است و `read`/`glob` فقط برای فایل‌هایی که کدگراف نام برده. منشی در کل
یک اجرا **دقیقاً یک** بار کدگراف صدا می‌زند، در ابتدای کار.

اگر `.codegraph/` نبود، اجرا با یک خط متوقف می‌شود — هرگز بازگشت خاموش به جست‌وجوی
متنی.

---

## ۹. پیکربندی و ری‌استارت

ایجنت‌ها در `.opencode/agent/` و کامندها در `.opencode/command/` هستند و وقتی ریپو
پوشه‌ی کاری باشد، خودکار بارگذاری می‌شوند. برای استفاده در همه‌ی پروژه‌های این ماشین:

```bash
make opencode      # کپی اسکیل‌ها، کامندها و ایجنت‌ها به ~/.config/opencode/
```

**بعد از هر تغییر زیر `.opencode/` یا در `opencode.jsonc`، opencode را restart کنید** —
کانفیگ hot-reload نمی‌شود.

## ۱۰. عیب‌یابی

| نشانه | علت | راه‌حل |
|---|---|---|
| کامند در پالت نیست | opencode ری‌استارت نشده | خارج شوید و دوباره باز کنید |
| «کدام کار؟» پرسیده شد | به `/go` verb ندادید | verb اضافه کنید یا از پریست استفاده کنید |
| ۳ کارگر اجرا شد | `-n` ندادید (پیش‌فرض ۳ است) | در انتهای خط `-n N` بگذارید |
| مرحله‌ای اجرا شد که نخواستید | اضافه‌شدن خودکار مرحله | در گزارش اعلام می‌شود؛ با پریست verbها را ثابت کنید |
| منشی از خواندن فایلی طفره رفت | عمدی است — او کد نمی‌خواند | از یک پریست/کارگر جزئیات بخواهید یا مستقیم `@` کارگر را صدا بزنید |
| `make test` دو بار اجرا شد | یک کارگر اجرا کرده (کانفیگ قدیمی) | ری‌استارت کنید، `bash` کارگر را چک کنید |
